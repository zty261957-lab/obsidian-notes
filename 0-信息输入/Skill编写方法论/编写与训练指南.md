# 拿到 Skill 模板后：如何自行编写与训练（7 步自学法）

> 目标读者：拿到《Skill 编写模板》的同事/学员。按此 7 步走，1-2 天能从"照抄"到"自己造"。

## 第 0 步：先装好环境（半天）
1. 装 Node.js + Git + VSCode + Claude Code CLI（或你已有的 AI 编程工具）
2. 配置大模型 API（CC Switch 或 settings.json；国产模型 Minimax/DeepSeek 即可）
3. 验证：终端输入 `claude` 能进对话

## 第 1 步：选一个"自己的场景"（30 分钟）
从你**本周真实要做的重复工作**里挑，别用课程示例：
- 你是产品经理 → 评审会纪要 / 用户反馈分析 / 周报 / PRD 初稿
- 你是测试 → 缺陷报告归类 / 测试用例生成
- 判断标准：每周 ≥2 次 + 流程稳 + 产出能模板化

## 第 2 步：解剖 1 个现成 Skill 找感觉（30 分钟）
打开一个参考 SKILL.md（如本包附的 meeting-minutes 完整版），做 3 件事：
1. 划出 frontmatter 与 6 模块边界
2. 找出"输出契约"里被写死的部分（板块/字段/路径）
3. 找出"约束"里每条对应的翻车点（为什么写这条？）

## 第 3 步：填模板出第一稿（1-2 小时，核心）
打开《1_Skill编写模板》，逐模块填：
1. name/description：想 5 个触发关键词
2. 执行步骤：**先写"我自己手工做这件事的步骤"**，再翻译成给 AI 的指令
3. 输出契约：把你最满意的一份历史产出拿过来，逆向提炼固定格式
4. 约束：对照第六节"翻车点表"逐条过一遍

> ⚠️ 新手最常见错误：跳过步骤直接让 AI 写 → 约束缺失 → 输出不可控。**先自己填一遍**，再让 AI 帮你润色。

## 第 4 步：放对位置并加载验证（10 分钟）
```bash
mkdir -p ~/.claude/skills/<skill-name>
# 把 SKILL.md 放进去
# 重启 claude 对话，输入 /skills 看是否出现
# 看不到 → 检查：①第一行是 --- 吗？②name 与目录名一致吗？
```

## 第 5 步：训练闭环（最重要的步骤！反复做 3-5 轮）
```
给 1 份真实输入 → 调 skill 跑 → 对照输出契约检查
    ↓ 发现问题（格式飘了/编人了/漏步骤）
把问题写成一条新约束 → 改 SKILL.md → 重跑
    ↓ 直到稳定
换 1 份不同风格的输入（残缺版） → 再跑 → 再补约束
```
**三组测试输入**：
| 输入类型 | 目的 |
|---------|------|
| 标准输入 | 验证主流程正确 |
| 残缺输入（缺名单/乱格式/超短） | 验证约束兜底（应标"待定"而非硬编） |
| 复杂输入（内容多/话题杂） | 验证切分与提炼质量 |

## 第 6 步：验收清单（全过 = 可以上岗）
- [ ] `/skills` 能加载，一句话能触发
- [ ] 同一输入跑 2 次，输出结构一致（格式稳定）
- [ ] 残缺输入不翻车（不编造、标待确认）
- [ ] 产出能直接交给同事用，不用大改
- [ ] 真实场景用 3 次以上，没再暴露新翻车点

## 第 7 步：持续迭代（长期）
- 每次实际使用发现问题 → 当场补约束（改一行就够）
- 产出模板沉淀进 skill 的 references/ 或 templates/
- 攒出稳定经验 → 分享给团队（放项目 .claude/skills/ 进 git）
- 规则：**先改自己的使用习惯/项目文件，确认通用后才反哺 skill 本体**

---

## 常见卡点急救
| 现象 | 原因 | 解法 |
|------|------|------|
| /skills 看不到 | frontmatter 缺 name | 第一行 `---`，第二行 `name:` |
| 触发不自动 | description 关键词少 | 补 5+ 触发词 |
| 输出每次不一样 | 输出契约没写死 | 补板块/字段/路径 |
| AI 编造内容 | 约束缺"不编造" | 加"只能来自输入，找不到标待确认" |
| 步骤漏做 | 执行步骤太粗 | 拆到 3-10 步动词开头 |
| 改一处全乱 | 单文件塞太多 | 升级外挂 templates/examples |

## 训练节奏建议
```
第 1 天：第 0-3 步（环境+选题+第一稿）
第 2 天：第 4-6 步（加载+训练闭环 3 轮+验收）
第 3 天起：真实场景使用，随手补约束
```
