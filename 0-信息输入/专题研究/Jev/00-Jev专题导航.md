# Jev 专题导航

> [!abstract] 一句话结论
> Jev 不是通用 LLM 的替代品，而是一个面向软件工作流的“低延迟、低成本、带概率的受约束判断层”。它适合分类、路由、打分、筛选和校验；不适合生成文本、复杂推理、精确计算或直接替代高风险决策人。

## 核心判断

### Jev 真正改变的是什么

- 把“请模型输出 JSON”改成原生的 typed decision：`Choice`、`Score`、`Noul`。
- 让应用代码掌握流程、阈值和动作，模型只负责难以写死的语义判断。
- 把概率与置信度变成可观察信号，允许自动执行、二次校验、人工复核三段式路由。
- 当同一状态需要多个独立判断时，可并行提问，减少重复输入和串行等待。

### 不应被宣传语带偏的地方

- “不会幻觉”只保证不会输出定义之外的类型或选项，不保证选中的答案正确。
- 官方的 `193.6×` 更快、`444.6×` 更便宜来自厂商自建 workflow eval，不能直接外推到企业真实场景。
- 概率校准不是跨任务、跨问题类型、跨模型版本自动成立；必须用自己的标注样本重测阈值。
- Jev 不提供自然语言解释。对审计、合规和高风险场景，仍需保留证据、规则命中、人工确认和可复现日志。

## 企业 AI / Agent 迁移框架

| 层级 | 建议职责 |
|---|---|
| 确定性代码 | 金额、日期、权限、状态机、配额、唯一性、最终执行条件 |
| Jev 类决策层 | 意图分类、风险分级、候选排序、是否升级、是否需要人工复核 |
| 通用 LLM | 复杂推理、规划、解释、生成文案、处理开放式答案 |
| 人工确认 | 高风险、低置信、规则冲突、不可逆操作、监管要求 |
| 观测与评测 | 记录模型版本、问题版本、概率、阈值、最终动作、人工纠正和真实结果 |

## 首批最值得验证的企业场景

1. **Agent 工具调用风险门**：读取、写入、删除、提权、外传分别分类；不可逆动作仍强制确认。
2. **工单/需求智能路由**：先判断业务域、紧急度和信息完整性，再交给专业 Agent 或人工。
3. **RAG 入口过滤**：判断候选片段是否相关、是否矛盾、是否含提示注入，再决定是否送入生成模型。
4. **模型级联**：简单、高置信任务走便宜模型；复杂、低置信任务升级到推理模型或人工。
5. **批量质量检查**：对 Agent trace、回复、引用和规则符合性做低成本抽检或全量检查。

## 采用前的最小验证门槛

- 用本企业真实数据建立标注集，至少覆盖正常、模糊、边界、对抗和缺失信息五类样本。
- 分别评估每个问题类型和业务动作，不共享阈值。
- 报告准确率之外的误报、漏报、覆盖率、校准误差、p50/p95 延迟、失败率和单次成本。
- 对中文、行业缩写和本地政策单独测试；官方明确说明英文效果最好。
- 固定模型版本；升级时重新跑回归集，不直接依赖会移动的 `jev-latest`。
- 所有高风险动作都保留确定性校验和人工确认，不因高置信度自动越权。

## 资料价值分级

- **A｜核心证据**：官方接口与限制文档、可复现代码/数据、预注册或有明确样本与方法的独立实测。
- **B｜重要背景**：可信媒体采访、平台采用数据、技术团队的深度解读。
- **C｜线索**：社区讨论、演示视频、未经复现的个人体验，只用于提出问题。
