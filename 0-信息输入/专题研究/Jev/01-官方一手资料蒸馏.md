# Jev 官方一手资料蒸馏

> [!summary] 阅读结论
> 官方资料最有价值的不是“更快更便宜”的口号，而是其工程边界：原子问题、代码控制流程、概率驱动路由，以及官方主动公开的九类失败模式。

## 1. Introducing System One Models & Jev

- **原文**：[Introducing System One Models & Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **来源类型**：官方发布文
- **价值等级**：A（理解产品定位必读；性能数字属于厂商自测）
- **核心观点**：Jev 接收非结构化状态和预先定义的问题，返回类型化概率决策；官方将其定位为“给软件调用的智能函数”，而不是给人阅读的聊天模型。
- **适用场景**：分类、路由、打分、筛选、验证、实时决策和批量处理。
- **争议/限制**：`193.6×` 更快、`444.6×` 更便宜来自 TypeSafe 自建的四个 workflow；参考答案是两个大型模型的平均意见，不是真实世界 ground truth。官方也承认样例由内部能力团队设计、速度从靠近服务端的美国西海岸测得、定价是否补贴需时间验证。
- **企业启发**：不要用 Jev 替换整个 Agent；只替换其中“答案空间已知、需要频繁执行”的判断节点。

## 2. System One、三种原语与 Confidence

- **原文**：[Introduction](https://docs.typesafe.ai/introduction)、[System One](https://docs.typesafe.ai/concepts/system-one)、[Confidence](https://docs.typesafe.ai/confidence)、[Patterns](https://docs.typesafe.ai/patterns)
- **来源类型**：官方技术文档
- **价值等级**：A
- **核心观点**：
  - `Choice`：在固定选项中选择，并返回每项概率与 confidence。
  - `Score`：在有序量表上评分，并返回各等级概率与 confidence。
  - `Noul`：判断一个命题为真的概率，直接返回 0–1，不另带 confidence。
  - 每个问题应是单一、直接、几秒内可判断的“原子问题”；复杂判断拆开后在代码中组合。
  - confidence 是从概率分布计算出的摘要，不是正确性的保证。
- **适用场景**：一份工单同时判断意图、紧急度、退款诉求和升级需要；一份 Agent trace 同时判断风险、偏航和人工复核优先级。
- **争议/限制**：官方没有公开 confidence 的完整统计定义；低置信可提示选项不完整、信息不足或问题含混，但模型不能主动生成“你漏掉了哪个选项”。
- **企业启发**：阈值必须绑定“具体问题 + 具体动作风险”，不能用一个全局阈值管理所有业务。

## 3. Models：版本、价格、上下文和数据边界

- **原文**：[Models](https://docs.typesafe.ai/models)
- **来源类型**：官方规格文档
- **价值等级**：A（会随版本变化，需定期复核）
- **当前信息（核验于 2026-09-21）**：
  - 稳定版本：`jev-1.13.0`；`jev-latest` 与 `jev-preview` 当前均指向它。
  - 价格：每百万输入 token 0.042 美元；输出不计费。
  - 上下文：每请求 64k；`state + 最长单个问题` 不超过 32k。
  - 输入：仅文本，可传字符串、JSON 或文本数组；不支持图像、音频和视频。
  - 语言：英语为主要训练语言，CJK 可处理但效果不等同，需自测。
  - 定制：不为单个客户微调；通过 state、instructions、criteria 和代码组合适配领域。
  - 数据：官方称不使用客户请求/响应训练；企业版提供零数据保留相关安排，具体以法律条款为准。
- **适用场景**：估算成本、设计版本固定策略、判断中文与多模态前处理要求。
- **争议/限制**：早期访问和限流会动态变化；使用别名会在后台升级模型，可能让已调好的阈值漂移。
- **企业启发**：生产环境固定具体版本，并把模型版本写入每条决策日志；升级必须跑回归集。

## 4. Jev 1.13 Jaggedness

- **原文**：[Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- **来源类型**：官方限制说明
- **价值等级**：A+（采用前最该读）
- **核心观点**：官方明确列出九类薄弱点：字面理解、数学与计数、日期时间比较、多跳间接推理、无关长上下文、对抗内容、指令与标准冲突、跨问题结构一致性、文本生成。
- **适用场景**：用于决定哪些步骤留在代码、哪些可交给 Jev。
- **争议/限制**：
  - 状态中的提示注入或误导文本会影响判断，Jev 不会自动把 state 当作敌对输入。
  - 两个互为否定的 Noul 概率不保证相加为 1；同一问题用 Noul 与 Choice 提问也不保证可直接比较。
  - 计数、算术、日期排序和精确数值应放回确定性代码。
- **企业启发**：把“模型知道什么”和“系统必须保证什么”分开；权限、金额、时间窗、状态机和不可逆动作永远由代码兜底。

## 5. Workflow Evals

- **原文**：[Workflow evals](https://evals.typesafe.ai/)
- **来源类型**：官方评测
- **价值等级**：A（理解测量方法）；B（证明普适性能）
- **核心观点**：评测把真实任务拆为多个窄问题，再用代码组合，覆盖安全事件、Agent trace 观测、发票处理和客服四类流程。官方结论是“结构化 workflow 普遍优于单一大提示词”。
- **适用场景**：学习怎样把业务规则和语义判断拆开，而不是把所有要求塞进一次 LLM 调用。
- **争议/限制**：所谓“accuracy”主要是与 GPT-6 Astra、Claude Fable 5.1 高思考结果的共识一致度，不等于人工或业务结果核验。
- **企业启发**：最值得迁移的是评测思路：冻结 workflow、固定问题、保存概率、用真实结果回标；不要只迁移排行榜数字。

## 6. Manifesto：Composable AI

- **原文**：[Composable AI: Build Prod, Not God](https://typesafe.ai/manifesto)
- **来源类型**：官方理念文章
- **价值等级**：B
- **核心观点**：AI 的瓶颈不只是智力，而是很难像数据库或函数一样被稳定组合；神经网络负责语义判断，代码负责精确计算与可审计分支。
- **适用场景**：企业 AI 架构原则、Agent 治理和人机分工设计。
- **争议/限制**：这是愿景，不是产品能力证明。
- **企业启发**：把 Agent 从“一个大模型包办一切”改造为“可观测、可替换、可验证的小决策节点 + 确定性控制流”。

## 官方资料的可信度边界

- **可以直接采信**：API 形态、当前价格、上下文、输入类型、版本、官方披露的限制。
- **需要企业自测**：准确率、概率校准、中文表现、阈值、p95 延迟、失败率和实际成本。
- **不能直接采信为普遍事实**：200×、400×、零幻觉、接近 frontier intelligence 等营销化表达。
