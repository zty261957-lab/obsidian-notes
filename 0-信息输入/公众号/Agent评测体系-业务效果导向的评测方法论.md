# 让Agent可评、可控、可迭代：业务效果导向的评测体系与场景实践

> **来源**：微信公众号「大淘宝技术」
> **原文**：https://mp.weixin.qq.com/s/gOCMe2lrO8PFGfZoKhUmfA
> **收录**：2026-09-18（Hermes 提炼整理）

## 📌 一句话概括

策略效果类 Agent 的评测难题是"**没有标准答案 + 反馈信号稀缺 + 离线合理≠线上有效**"；大淘宝提出 **「五层、四步、三阶段」方法论** + **Auto Rubrics 方法**，把评测从"静态判断"升级为"**动态闭环**"，让策略生成能力真正可扩、可控、可回归。

---

## 🎯 核心观点

### 1. 策略效果类 Agent 与任务型 Agent 的本质区别

| | 任务型 Agent（问答/摘要/代码） | **策略效果类 Agent** |
|---|---|---|
| **输出性质** | 可静态判定的"答案" | **会进入真实业务执行的策略配置** |
| **有无标准答案** | 有 | **没有确定性标准答案** |
| **质量验证方式** | 直接判断对错 | **只能靠大盘指标事后验证** |
| **评测的本质** | 判断"对错" | 判断"**在多个可接受策略中，谁更值得上线**" |

### 2. 三大核心难题

| # | 难题 | 说明 |
|---|------|------|
| **1** | **反馈信号稀缺且延迟** | 线上 A/B 实验是获取真实偏好的主要途径，但成本高、周期长 |
| **2** | **评估需要多维权衡** | 补贴/投放/素材等策略与 ROI、GMV、访购率之间不存在稳定相关性 |
| **3** | **离线与线上脱节** | 离线看起来合理的策略，到线上受环境、货盘、周期、流量影响；**线上指标变化不能直接归因为策略质量** |

### 3. 方法论框架：「五层、四步、三阶段」

```
五层评测对象  →  评什么  （L1 Prompt 约束 → L5 业务效果）
四步质量归因  →  评完怎么办（诊断 → 定位 → 优化 → 验证）
三阶段上线治理 →  如何上线（准入 → 灰度 → 监控）
```

#### 五层评测对象（逐层传导关系）

| 层级 | 评测对象 | 传导影响（原文关键判断） |
|------|---------|----------------------|
| **L1** | Prompt 约束 | **L1 → L3**：约束定义不清，模型行为就会**持续漂移** |
| **L2** | 决策依据 | **L2 → L4**：决策依据错误，策略方向**必然出现效果偏差** |
| **L3** | 执行链路 | **L3 → L4**：执行链路出错，输出**直接不可用** |
| **L4** | 输出质量 | — |
| **L5** | **业务效果** | 最终目标，只能用大盘指标验证 |

#### 四步质量归因

```
诊断（问题在哪一层）→ 定位（具体哪条规则/链路）→ 优化（改什么）→ 验证（改后是否真的变好）
```

#### 三阶段上线治理

```
准入（上线前门槛）→ 灰度（小流量验证）→ 监控（持续跟踪）
```

### 4. LLM-as-Judge 的三个系统性陷阱 ⚠️（本文最有价值的部分）

| # | 陷阱 | 表现 | 危害 |
|---|------|------|------|
| **1** | **位置偏差** | 模型倾向选择位置靠前的答案 | 能刷出**虚假的 96% 准确率** |
| **2** | **选择过拟合** | 换一批样本就选出**完全不同的 Rubric** | 评测标准不稳定，无法复用 |
| **3** | **一致性 ≠ 正确性** | 稳定地判错 | **比不稳定更危险**（错误被"稳定"地固化） |

### 5. Auto Rubrics 方法：解决"离线评测可信度"

**核心思路**：让**业务效果 Rubric（评测规则）从数据中自动挖掘**，而不是人工拍脑袋定义。

**三层架构**：

| 层 | 名称 | 作用 |
|---|------|------|
| **Layer 1** | **供给层** | 从偏好对数据中**自动挖掘候选评测规则**，构建**数百条规模的候选池** |

**候选规则的两条挖掘路线**：
- **路线一**：对比挖掘隐性规则
- **路线二**：数据模式分析 + 多轮采样

**三个落地方案**：

| 方案 | 做法 | 解决的问题 |
|------|------|-----------|
| **方案一** | **双侧验证** | 验证规则有效性 |
| **方案二** | **比较评估 + 位置交换一致性** | 消除**位置偏差** |
| **方案三** | **稳定性筛选 + 交叉验证贪心选择** | 避免**选择过拟合** |

**★ 方案二的关键：问题重构**

| | 问题设计 | 效果 |
|---|---------|------|
| **旧问题** | "这个输出**是否违反**规则 X？" | 模型**无参照**，结论不稳定（一致率仅 **46%**） |
| **新问题** | "**A 和 B 两个输出，哪个在规则 X 上违反得更严重？**" | **强制三步推理**：分析 A → 分析 B → 对比结论 → **一致率提升至 84%** ✅ |

**方案三的关键判断**：
> 某条规则"**频率低**"→ 说明它只在**某些特定数据上被选中** → 是在**拟合噪声** → **不稳健**，应剔除。

**与传统 Reward Model 对比**：文章提到 Auto Rubrics 在可解释性上优于传统 Reward Model（后者是黑盒打分）。

### 6. 同一方法论的延伸：最优策略收敛判断（四层漏斗）

**用途**：判断"某个商品的策略是否已经收敛到最优"。

| 层 | 过滤条件 | 核心判断 |
|---|---------|---------|
| **Layer 1** | **量级过滤** | "**没有足够的数据，什么结论都不可信**" |
| **Layer 2** | **时间一致性** | "**今天涨不算，连续涨才算**" |
| **Layer 3** | **稳定性评分** | "**达标天数短和达标天数长不是一回事**" |
| **Layer 4** | **贪心组合验证** | "**单个商品不可信，组合才可信**" |

### 7. 如何衡量业务效果的变化（数据集与指标）

- **数据集的构建**：是评测可信度的前提
- **指标变化分档**：文章给出分档判断（`<-3pt` / `-3pt~-2pt` / `-2pt~-1pt` / `-1pt~0` / `0~0.5pt` / `0.5pt~1pt`）→ **按变化幅度分级响应**

## 🧠 关键概念速查

| 概念 | 含义 |
|------|------|
| **策略效果类 Agent** | 输出不是"答案"而是"会执行并影响大盘指标的策略配置" |
| **healthBest 策略** | 帕累托最优策略（历史最佳） |

| **Auto Rubrics** | 自动挖掘评测规则（Rubric）的方法 |
| **位置偏差** | 模型偏好靠前的选项 → 产生虚假高分 |
| **选择过拟合** | 评测规则对样本过拟合，换样本就失效 |
| **Rubric** | 评测规则/评分标准 |
| **四层漏斗** | 逐层过滤噪声，判断策略是否收敛 |

## 🔑 可迁移到我们工作的点

| # | 文章观点 | 对我们的启示 |
|---|---------|-------------|
| **1** | **五层评测对象**（L1 约束 → L5 业务效果） | ⭐ **可直接用于我们"评测集"任务的分层设计** —— 明确"评什么"，避免只评输出不评效果 |
| **2** | **L1→L3 传导**："约束定义不清，模型行为持续漂移" | 呼应我们 Skill 规范里的**"约束必须写清"**（MUST/MUST NOT）—— 约束不清是质量漂移的**根因** |
| **3** | **三阶段上线治理**（准入/灰度/监控） | ⭐ 可借鉴到我们的 **Skill 上线流程**（现在已经写进培训手册的"发布与维护"章节） |
| **4** | **LLM-as-Judge 三陷阱** | ⚠️ 我们用大模型做质检/验收时，**必须防位置偏差与过拟合** —— 不能只看"一致率高"就认为可信 |
| **5** | **问题重构**（从"是否违反"到"哪个更严重"） | ⭐ **写 Prompt/评测项时的实用技巧**：给模型**参照系**，一致率能从 46% 提到 84% |
| **6** | **"频率低 = 在拟合噪声"** | 判断规则是否稳健的**可操作判据** |
| **7** | **四层漏斗** | 用于判断"改动是否真的带来提升"——**量级不够就不下结论、单次涨不算涨** |
