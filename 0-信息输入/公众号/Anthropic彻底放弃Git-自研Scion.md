# Anthropic 已经彻底放弃 Git 了

> **一句话结论**：**AI 写代码太快，Git 这种"为人类程序员设计"的基础设施成了瓶颈** ——
> **他们用 5 个月、7 个人做完了整套替换。**

---

## ⭐ 一、为什么换（数据很吓人）

| 指标 | 数据 |
|------|------|
| **每天合并代码** | **5 月约 2,500 次 → 9 月超 3 万次**（**4 个月涨 12 倍**）|
| **代码仓库** | Monorepo **主分支历史 100GB**、工作副本 **25GB** |
| **每天代码检出** | 约 **2,500 万次** |
| **理论日传输量** | **超 600PB** |

**⚠️ Git 为什么成瓶颈**：
> 每次变更都要**取代码 → 查历史 → 比差异 → 合并 → 触发测试**
> —— 规模涨十几倍后，**原来的"几秒几十秒"累积成了巨大消耗**。

**⭐ 之前试过的所有优化**（浅克隆/稀疏检出/镜像/快照 + **几百台镜像服务器**）——
**"治标不治本"**。

---

## ⭐⭐ 二、Scion 的三个设计改变

| # | 改变 | 说明 |
|:--:|------|------|
| **1** ⭐ | **客户端轻量化** | Git 的前提是"程序员要本地存完整仓库"（因为可能离线）<br>**但现在访问仓库的绝大多数是 Agent，它们始终联网**<br>→ **Agent 只要它需要的那几个文件** |
| **2** | **重活交给服务端** | **Commit / Merge / Rebase / 查历史 / 比差异 —— 全部由服务端 API 完成** |
| **3** | **存储与多级缓存** | ① 只记录变化的文件（哈希识别复用）<br>② **多级缓存：本地 → 区域 → 服务端，每层命中率 >99%**<br>③ 分布式存储，加机器就扩容 |

---

## ⭐⭐ 三、效果（数字很夸张）

| 指标 | 之前 | 之后 | 提升 |
|------|:----:|:----:|:----:|
| **创建 Worktree** | **7.1 分钟** | **5.1 秒** | ⭐ **84 倍** |
| **拉取最新代码** | 3 分钟 | **9 秒** | **20 倍** |
| **变更中版本控制耗时** | 34 分钟 | **3.7 分钟** | **9 倍** |
| **CPU/内存需求** | — | — | ⭐ **缩小 200 倍** |
| **每天节省** | — | **1.1 万个 Agent 小时** | — |

---

## ⭐⭐ 四、最惊人的细节

> **5 个月、7 个人**，完成 Scion + 整个仓库迁移；
> **同期还做了**代码审查工具（Antique）+ 代码搜索 + 权限管理。

**⭐ 而且他们大量用 Claude 参与开发**：
> 原来**工程师手写**的 Git→Scion 数据导入程序（"大家觉得已经写得很好了"）——
> **让 Claude 重写后：内存降低 20 倍、速度快 4 倍，还保留了原代码里的隐含约束。**

**⭐ 作者的感叹**：
> **"这才是真正的 Loop Engineering。"**

---

## ⭐⭐⭐ 五、核心洞察（**最有价值**）

> **"过去几十年，几乎所有的软件开发工具，都是围绕人类程序员的工作习惯设计的。**
> **人需要离线开发、需要在本地保存代码、需要自己完成大量版本管理操作。**
> **这些需求影响了 Git，也影响了整个软件开发流程。"**
>
> ### **"但现在，越来越多的代码开始由 Agent 编写 ——
> ### 它们的工作方式、并发规模、对工具的需求，都和人类程序员有很大差别。
> ### 原来那些看起来非常合理的设计，可能都需要重新考虑了。"** ⭐
>
> ### **"AI 时代，所有的软件都会重新做一遍。**
> ### **今天是 Git，接下来可能就是 CI、代码审查、软件测试……"** ⚠️
>
> ### **"当写代码越来越便宜，整个软件工程中那些原本不太起眼的环节，可能会一个接一个地成为新的瓶颈。"** ⭐

**⚠️ 作者也说了**：
> **Scion 不适合绝大多数公司**（很少有公司每天几万次代码变更）
> **但 Anthropic 预计未来 6-12 个月，越来越多 AI 编程公司会遇到类似问题。**
