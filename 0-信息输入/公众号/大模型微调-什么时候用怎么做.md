# 大模型微调：什么时候用、怎么做、AI 产品经理怎么决策

> **一句话结论**：**微调不是用来"补知识"的，是用来"规范输出"的** —— 知识用 RAG，风格/格式用微调。

## 一、什么时候该考虑微调

**同时满足这三条**才考虑：

1. 模型**需要某领域的知识/能力**，但**不会按你的格式输出**
2. 它在某个**垂直领域表现不稳定、不专业**
3. **你有足够多的高质量历史数据**

---

## ⚠️ 先破除一个误解：微调 ≠ 让模型学新知识

| 常见误解 | 实际情况 |
|---------|---------|
| 模型"不知道"怎么写合同 / 客服怎么回 / 日报怎么整理 | **千问、GPT 已经通过海量数据预训练过了，它知道** |
| 所以要用微调"教"它 | ❌ 真正的问题是：**它不按"我公司的风格、格式、语气"来说话** |

> **这才是微调要解决的问题** —— 不是"不知道"，而是"不按我们的规矩说"。

## 二、大模型微调是怎么做的

### 类比：把大模型想象成一个实习生

| 阶段 | 类比 | 含义 |
|------|------|------|
| **预训练** | 读了**整个图书馆的书** | 知识广博（知道合同怎么写、客服怎么回） |
| **微调** | 带他**进公司**，给他看 **100 份你们之前的合同**，告诉他"以后都按这个格式写，不准自由发挥" | 学会你们公司的规矩 |

### 技术步骤（四步）

| 步 | 做什么 | 关键数字 |
|----|--------|---------|
| **1** | **准备数据**：从历史材料中提取「**输入 → 输出**」配对样本 | **至少 100~500 条高质量样本** |
| **2** | **选择基础模型** | 如**千问**（支持微调） |
| **3** | **启动微调任务**：上传数据集、设置训练参数（**学习率、轮数**），然后跑训练 | 训练 **几小时 ~ 一天**；成本 **几百 ~ 几千元**（依数据量与模型大小） |
| **4** | **得到新模型** | 效果："只要给我这几个字段，就能按公司模板出合同" |

## 三、AI 产品经理如何决策（★核心）

### 决策路径

```
用户需求来了
   ↓
① 能不能通过 Prompt + 检索（RAG）解决？
   → 能 → 优先用 RAG / PE 工程 ✅
        （80% 的问题都能解决）
   ↓ 不能
② 有没有足够高质量的历史数据？
   → 有   → 可以微调
   → 没有 → 先积累数据，或考虑「小模型 + 规则」兜底
```

### 四条铁律

| # | 铁律 | 说明 |
|---|------|------|
| **1** | **不要一上来就想着微调** | 先试 Prompt 优化、RAG —— **80% 的问题都能解决** |
| **2** | **微调用来规范化输出，不是用来补知识** | **知识直接用 RAG 就行** |
| **3** | **风格问题 → 才需要用微调** | 这是微调的主场 |
| **4** | **微调是成本行为，要有 ROI 思维** | 算清楚：**节省的人力时间成本 ≥ 微调的投入成本？** |

## 四、决策速查表

| 你遇到的问题 | 该用什么 |
|------------|---------|
| 模型**不知道**某知识 | **RAG**（检索知识库） |
| 模型**知道但输出格式不对** | **微调** |
| 模型**知道但语气/风格不像我们** | **微调** |
| 模型**知道但输出不稳定** | 先用 Prompt 约束 → 不够再考虑微调 |
| **数据不够** | **先积累数据**，或用「小模型 + 规则」兜底 |
| **不确定用什么** | 先试 Prompt + RAG（成本最低，覆盖 80%） |

---

## 五、一句话记忆

> - **知识问题** → 用 **RAG**
> - **风格/格式问题** → 用 **微调**
> - **拿不准** → 先 **Prompt + RAG**，不行再谈微调
> - **要微调** → 先算 **ROI**（省的人力时间 ≥ 投入成本吗？）
