# FDE 落地一页速查卡

> 从《FDE 初探营实战手册》+《AI Agent 锻造师实战手册》提炼 ｜ 2026-09-23

---

## ① 先判断：这单接不接？（客户三层）

| 层 | 特征 | 结论 |
|---|------|------|
| **1 未信息化** | 纸质单据 / Excel 传 / 微信群吼 | ⭐ **最好做，没有之一**（无包袱·需求具体·老板拍板）|
| **2 信息化** | 有系统，要把 AI 引进现有系统 | ⚠️ **单子肥但骨头难啃**（结合点难挖·存量对接难·组织惯性）<br>→ **先深挖再报价 + 提效量化成大白话 + 边界写进合同** |
| **3 数字化** | 数据已通，AI 只做**决策** | ⚠️ **不是一个人能接的**（需团队级作战体系）|

**旁证**：看老板用什么工具 —— **豆包=认知层　智能体工具=部署意愿层　agent+data+FDE=实战部署层**

## ② 进场三步

```
1. 流程梳理 + 机会识别：一级拆到二三级，逐个节点问「在干什么？能不能交给 AI？」
   ⭐ 节点分三类：执行（最适合AI）／审核（数据规则可判→AI，需经验→人）／审批（留人）
   ⚠️ 「为了审而审」的节点直接删掉
2. 技术验证：收最小样本集 → 敏捷做出 Demo → 让客户有直观感受
3. ROI 评估 + 上线：和客户一起算投入产出比 → 共识落地规划 → 开发上线
   ⚠️ 上线不是结束：建评估系统，随业务和模型变化持续校准
```

## ③ ⭐ 需求深挖五问（最重要）

```
① 挖动机：连续问 3–5 层「为什么」，直到能说清「这功能为什么非存在不可」
② 挖场景：角色 / 触发时机 / 要完成的任务 / 使用频率（4 要素）
③ 挖边界：正向问验收标准 + 反向问排除项 → 验收标准 + 边界清单
④ 挖异常：空数据 / 涨10倍 / 依赖中断 / 操作出错能撤回吗 / 安全合规（涉密·国产化·脱敏·留存）
⑤ 挖约束：规矩、合规、其他限制
```

**收口公式**：
> **让【某角色】在【某场景】下办成【某目标】，做到【什么边界】，出事了【怎么兜】，同时受【哪些规矩】管着。**

**三个即用判断**：
- ⭐ **没行动的需求都是伪需求**（没花过钱/没派过人/没花过时间）
- ⭐ **客户说三遍的，一定是真正要的需求**
- ⭐ **客户要的是 X，追问「X 解决了什么问题」—— X 是解决方案，问题才是需求**

**⚠️ 访谈铁律**：先观察再访谈（群聊里反复出现的问题/@的人/等待的环节 = 真实痛点地图）；
**必须访谈至少 1 个一线执行者**（老板说的是「应该怎样」，一线说的才是「实际怎样」）；**访谈阶段只听不说方案**

## ④ 怎么排优先级：四维评分

```
痛点 Pain        0.35   ← 最重要（直接关联 KPI + 痛点强度）
ROI  杠杆        0.25
数据 Data        0.20   （有没有 / 质量如何 / 有没有权限）
可行性 Feasibility 0.20 （标准LLM+Agent可解=4-5分）
────────────────────────────
⭐ 硬规则：Feasibility ≥ 4，才能保证两周跑出原型
```

**产出三档**：Tier A 快速验证（0–2 周）｜ Tier B（有价值但现在做不了 → 写成 Roadmap）｜ 暂不做

**⚠️ 五个陷阱**：用技术反推场景（必落到玩具）｜ 忽略数据权限（交付即翻车）｜ 评分拍脑袋 ｜ 不挖需求就报价 ｜ 范围不写边界

## ⑤ 怎么收钱

**报价四级**（先判断客户在为什么买单）
```
① 诊断收费 —— 卖的是判断，不是代码
② 方案收费 —— 客户买的不是 PPT，是一条少走弯路的路径
③ 部署收费 —— 按人天/阶段/里程碑（⚠️ 只会部署的替代性最强、价格最低）
④ 结果收费 —— 和项目价值/节省成本/新增收益挂钩
```

**⭐ 诊断开口话术**：
> 「**我们先做一个 2 周的诊断项目，交付一份场景诊断报告和优先级建议，费用是 X。如果后续合作，这笔费用可以全额抵扣。**」
> （⚠️ 别说「我们要收诊断费」；别按天收；能用固定费用 + 抵扣）

**⭐ 防白嫖三原则**
```
① 免费只做诊断，不做交付（不免费画完整架构、不免费给能运行的方案）
② 把工作拆成阶段（诊断/方案/MVP/部署各有各的价 + 各有产物/时间/验收标准）
③ 先收启动款，再打开深度权限（真实数据/流程/接口都是交付资源）
```

**⚠️ 两个必须**：
- **不要按「陪聊了多久」报价，要按「帮客户减少了多少成本、拿到了什么结果」**
- **算力成本不要打包进固定费用**（服务器数据库是固定成本可算，模型调用是波动的 → 报价含额度，超出客户自充）

**报价单至少六项**：交付什么 / 客户提供什么 / 周期 / 确认验收方式 / 试运行多久 / **哪些不包含**

## ⑥ 第一份交付物：诊断报告（5–8 页）

```
① 背景摘要（半页）：行业和业务模式 + 关键 KPI（现状→目标）+ 痛点强度（用数字）
② 场景排名表（核心）：场景名 / 一句话商业逻辑 / 可量化成功指标 / 两周原型计划
③ 推荐快速验证场景：「我们建议先做这个，两周能看到效果」
④ 风险与数据缺口：坦诚说明不确定性
⭐ 结尾必须有明确的「下一步建议」
```

**⭐ 成功的标志**：**客户能立刻说「先做这个」，且知道为什么、能得到什么、有什么风险。**
⚠️ **如果客户还犹豫做哪个，说明诊断不聚焦，回去重新访谈。**

## ⑦ 交付三纪律（防扯皮）

```
① 交付前自检：按「合同 / 需求确认单 / 功能清单 / 测试报告」逐项查（没超范围、没漏项）
② 阶段同步：原型 / 静态页 / 数据同步 / 助手 —— 每段确认一次，别等交付当天说做不完
③ 验收卡新需求：客户看到成品产生新想法很正常 → 先判断「小修正」还是「新需求」；
   新功能模块/新接口/新表结构/新权限 → 记下来放下轮迭代（保护第一版按时完成）
```

**两个方案的写法**：**部署方案 = 别人照着做也能完成**；**迁移方案 = 出问题也能退回去**
⚠️ **方案没经过一次完整演练，只能算草稿，不能算交付文档。**
⚠️ **合同签订前必须确认：是否包含国产化/信创改造**（换个中间件就能让工作量翻倍）。

## ⑧ 做交付物时（Skill / Agent）

**数字员工 8 条自查**
```
□ 1. 先有岗位，再有 AI（岗位是谁？）
□ 2. 职责清晰（负责什么 / 不负责什么 / 交付什么）
□ 3. 有自己的知识和上下文
□ 4. 有标准工作流程（输入→判断→执行→输出）
□ 5. 能主动执行（不只是「你问我答」）
□ 6. 有权限和边界（可自主 / 必须问人 / 绝对不做）
□ 7. 有反馈、协作、异常处理
□ 8. 形成迭代闭环
```

**四段式拆解**
```
输入（宁可多不可少）→ 处理（①②③每步一个动作）→ ⭐判断（能用「是/否」判）→ 输出（格式+字段）
```

**⭐ 三条最要命的**
- **判断标准缺失或太软 = 产出「时好时坏」的头号病根**
- **提示词是「这一次怎么干」；Skill 是「以后都这么干」**
- **优化一次只解决一个问题，并用同一个输入复测**

## ⑨ ⭐ 三句话（记这三句就够）

> **1. AI 落地大多数项目失败，不是技术不行，而是需求从一开始就理解错了。**
> —— 所以「需求深挖五问」永远排第一。

> **2. 不要按「陪聊了多久」报价，要按「帮客户减少了多少成本、拿到了什么结果」。**
> —— 你卖的是判断、方案、部署和结果，不是工时。

> **3. 客户愿意继续付费，不是因为某次代码写得多好，而是因为「能持续稳定地把事情做下去」。**
> —— 复购来自可复用的方法论，不是一次交付的漂亮。

## ⑩ 空手出门也要带的四句

| 场景 | 说什么 |
|------|-------|
| **客户说「我想要 X」** | 「**X 能解决什么问题？**」（追问三层为什么）|
| **客户说不出 KPI** | 「**老板最近在会上反复提什么？什么事让他睡不着觉？**」 |
| **客户要免费方案** | 「**我们先做 2 周诊断（交付报告 + 优先级建议），费用 X，后续合作可全额抵扣。**」 |
| **客户加新需求** | 「**这个属于新需求，我记下来放下轮排期 —— 先把第一版验收完。**」 |
