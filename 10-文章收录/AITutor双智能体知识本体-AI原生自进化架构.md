## 📌 一句话概括

AITutor 用**两个职责分离的智能体 + 一个知识本体经验库**，把"内容生产"和"内容保鲜"都变成系统的自动能力——模型能力是买来的，**真正拉开差距的是系统上线后还能不能自己变强**。

## 🎯 核心观点（提炼）

1. **"跑通即巅峰"是 AI 应用的普遍困境**：Demo 阶段惊艳，上线三个月开始退化，半年后没人敢用——因为能力在交付那一刻被冻结了。
2. **知识半衰期已压缩到"周"**：更新速度低于知识过期速度，系统就在持续腐化。
3. **必须拆成两个智能体**：「新知识进来」（从无到有的生产）和「旧知识过期」（从有到优的判定）是**两个方向相反的问题**；一个智能体同时扛，**提示词互相污染、评估标准互相干扰**。职责分离在 Agent 架构里和微服务架构里一样重要。
4. **经验闭环是核心资产**：每一次执行前先拉历史经验（不是写死的规则），执行后反馈沉淀——形成"知识经验拉取 → 实时执行 → 反馈沉淀"的小闭环。
5. **批注有方向**：分正向与负向——**负反馈纠偏，正反馈固化**，比只做纠错的系统收敛快得多。
6. **"禁止人工手写正文"是硬约束**：不是为省人力，而是**保证经验闭环不被污染**——一旦允许人工插手，生成质量就无法归因到提示词和经验，反馈信号就断了。要让系统自己学，就必须让它承担全部输出。
7. **人工审核是核心进化触发点**：审核不通过 ≠ 打回重做，而是**自动沉淀问题经验 → 存入经验库 → 回流至素材筛选 → 基于新经验重新检索改写**。一次不通过 = 整条链路判断力的一次升级。
8. **白名单观察机制**：判不准的内容不强行决策，挂起观察一个月后自动回流重评——"杜绝知识遗漏和误删，靠的不是更聪明的模型，是一个愿意承认'现在判不了'的机制"。
9. **护城河不在模型选型**：能力**不长在模型参数里，长在经验库里**——模型可随时换，但经验库是自己跑出来、别人拿不走的资产，且随使用量增加而变厚。
10. **两条曲线的分野**：有闭环的系统**越用越准**；没闭环的系统**交付即巅峰**。

## 📖 正文（完整保留）

### 一、所有 AI 内容产品，都绕不开的那个死结

做 AI 应用这三年多，我见过太多"跑通即巅峰"的 Agent。Demo 阶段惊艳，上线三个月开始退化，半年后没人敢用，因为它的能力是在交付那一刻被冻结的，之后只会随着世界的变化而相对变差。

模型能力是买来的，谁都能买。真正拉开差距的，是系统在上线之后还能不能自己变强。

先说问题本身。任何做知识型产品的团队，都会同时被三件事拖住：

1. **前沿性不足**：新技术出现到进入课程体系，中间隔着漫长的人工周期
2. **存量过时**：已上线的内容没人回头看，框架版本早就变了，案例早就废了
3. **成本高昂**：内容的生产、审核、更新，全部依赖人工，规模化即崩溃

传统解法是堆人，招更多老师、排更密的更新计划。但这条路的天花板极低：人工运维的效率瓶颈和认知局限，是没办法靠增加人数绕过去的。

而 AI 时代，知识的半衰期已经压缩到了"周"。你的更新速度只要低于知识过期的速度，系统就在持续腐化。

所以我们没有从"怎么更新得更快"入手，而是换了个问法：**能不能让知识的生产和保鲜，不再依赖人的推动？**

### 二、答案：把"更新"这件事，拆成两个智能体

整套体系基于 Hermes 通用引擎搭建，核心是两个职责完全不同的智能体：

```
                    Hermes 通用引擎
        ┌─────────────────────┴─────────────────────┐
        ▼                                           ▼
  自动生成课程智能体                          自动迭代课程智能体
     （增量进化）                                （存量焕新）
   解决：新知识供给                            解决：旧知识更新
        │                                           │
        └─────────────────┬─────────────────────────┘
                          ▼
                    知识本体经验库
              沉淀 · 复用 · 反哺全链路
```

**为什么必须是两个，而不是一个？**

因为"新知识进来"和"旧知识过期"是两个方向完全相反的问题。前者是从无到有的生产问题，链路是 采集 → 筛选 → 创作 → 评估 → 上线；后者是从有到优的判定问题，链路是 体检 → 打分 → 定位过时点 → 重写。

一个智能体同时扛这两件事，**提示词会互相污染，评估标准会互相干扰**。职责分离，在 Agent 架构里和在微服务架构里一样重要。

而底下那个「标准化经验库」，才是全文的重点。

### 三、增量进化：自主生成课程智能体

这个智能体负责新知识供给，全流程分两大阶段，无需大规模人工干预。

#### 3.1 主题采集聚合：从噪音里捞出值得做成课程的东西

前沿知识散落在公开渠道里，绝大部分是噪音。这一阶段的目标只有一个：筛出具备课程开发价值的主题。

**三层技术链路**，每层之间都嵌了经验进化节点：

```
前置准备：建立稳定采集会话
   ↓
阶段一 · 采集（data_collect_layer）
  拉取优质来源白名单 → 串行抓取最新内容（5–10s 间隔）
   ↓ ↩ 拉取历史清洗经验
阶段二 · 清洗（data_clean_layer）
  LLM 分类去广告 → 核心摘要提取 → 采集点赞/分享等传播数据 → 结合历史过滤经验剔除低质内容
   ↓ ↩ 拉取聚合经验
阶段三 · 聚合（data_aggregate_layer）
  话题聚类 → 依托知识库去重 → 上报服务器归档 → 清空本地目录
   ↓
完成：合格主题进入 topic-agent 任务库，等待写作层调用
```

注意每一层之间那个 ↩。**采集之前先拉清洗经验，清洗之后再拉聚合经验**。每一次执行，用的都不是写死的规则，而是系统到目前为止积累下来的最新判断标准。

这就形成了第一个小闭环：**知识经验拉取 → 实时执行 → 反馈沉淀**。

而经验从哪来？**来自人的一次点击。**

在管理后台，运营看到一篇本不该被采进来的内容，点【批注】，选择批注类型为「过滤」，写下原因；看到聚合策略把两个不相干的主题并到了一起，点【批注】，选择类型为「聚合」。

批注一旦提交，智能体就吸收了这条经验。下一次采集和聚合，用的就是更新后的标准。

**设计细节**：批注是**有方向**的，分正向和负向。不只是告诉系统"这条错了"，也可以告诉它"这条判得很对，以后照这个来"。**负反馈纠偏，正反馈固化**，这比只做纠错的系统收敛得快得多。

#### 3.2 AI 课程生成：八步标准化生产链路

拿到优质主题后，生成流程全自动跑完八步：

```
步骤 1  claim_topic        从 topic-agent 领取待写主题（无可领主题则自动终止本轮，不空转）
   ↓
步骤 2-3 搜索并过滤资料     构造精准搜索词 → 检索千万级本地知识库 ← 拉取经验（过滤）
                          + 公开优质素材 → 逐条过滤
   ↓
步骤 4  大模型写课件        按课程级别匹配专属提示词 ← 基于经验（写作）
                          → 交大模型逐章节生成正文（禁止人工手写正文）
   ↓
步骤 4.3-4.4 插画 + 音视频  逐章生图上传 OSS → 产出 video.md / audio.md
   ↓
步骤 5  AI 评估            按远端经验对全部章节 0-100 标准化打分 ← 基于经验（评估）
                          → 写回 topic.json
   ↓
步骤 6  合并上报 submit     评估并入 article.json → 提交服务器，返回 articleId
   ↓
步骤 7  人工审核           内容质量 / 事实准确性 / 合规性
                          ├── 不通过 → 问题经验自动沉淀 → 回流至步骤 2-3，重新检索改写
                          └── 通过
   ↓
步骤 8  上线               正式发布，归入线上知识库
```

**三个关键设计点：**

**第一，"禁止人工手写正文"是硬约束。**
这不是为了省人力，是为了保证经验闭环不被污染。一旦允许人工插手正文，生成质量的好坏就无法归因到提示词和经验上，整个自进化机制的反馈信号就断了。要让系统自己学会，就必须让它自己承担全部输出。

**第二，课程级别决定提示词模板。**
L1、L2、L3 三个级别对应完全不同的提示词。同一个主题，做成"落地企业 AI 应用"和做成"落地系统级 AI 应用"，讲解深度、案例复杂度、代码颗粒度都不一样。**级别不是标签，是生成策略**。

**第三，人工审核是整个智能体的核心进化触发点。**
这是最关键的设计。审核不通过时，系统做的不是简单打回重做，而是：

```
审核不通过
   ↓ 自动沉淀问题经验 → 存入知识本体经验库
   ↓ 回流至素材筛选环节
   ↓ 基于新经验重新检索素材、改写课程内容
```

一次审核不通过，换来的不只是一门课的修正，而是**整条生产链路判断力的一次升级**。

后台的批注同样细分成三类：**【检索资料】【课程生成】【AI 评估】**。
- 搜索出来的资料过滤策略不对 → 走【检索资料】
- 课程生成的逻辑、格式不对 → 走【课程生成】
- AI 评估的打分标尺不准 → 走【AI 评估】

三类批注对应**三个不同的经验子库，各自反哺各自的环节，互不干扰**。反馈提交后，新经验与历史经验自动融合，下一次生成直接拉取最新版本。

审核通过后点【上线】，课程归入线上知识库，前端立刻可被检索和学习；觉得不行则【重新生成】或【生成弃用】。

### 四、存量焕新：让已上线的课程自己"体检"

新知识的问题解决了，还有更隐蔽的那一半：已经上线的内容，正在悄悄过期。

自动自主迭代课程智能体负责这件事，机制是**定时体检 + 经验驱动**：

```
定时任务：周期性触发知识库体检
   ↓ ↻ 拉取历史评估经验（校准本轮评估标尺与判定阈值）
阶段一 · 知识库过时评估（Skills）
   ① 框架工具是否过时？
   ② 技术方案是否仍先进？
   ③ 知识内容是否依然准确？
   → 输出：评估分数 + 改进方向
   ↓
阶段二 · 知识库迭代通知
   按评估结果生成标准化优化清单 → 同步至前端
   ↓
人工复核
   ├── 认可 → 带上评估给出的改进方向，走课程重新生成流程
   └── 存疑 → 放入白名单观察一个月
              ↓ 期满自动回流至体检任务，重新参与评估（闭环）
```

**两个关键设计：**

**其一，每轮体检前先校准标尺。**
如果每次体检用的都是当下临时的判断标准，迭代结果就会飘。先拉历史评估经验校准阈值，等于给系统装了一把**会随经验变精准、但在单轮内保持稳定**的尺子。避免判定标准混乱、迭代偏差。

**其二，白名单观察机制。**
人工复核存疑的内容，既不直接更新，也不直接放弃，而是挂起观察一个月，期满自动回流重新评估。

这是在处理一类很真实的情况：有些技术方案，在某个时间点上你判断不了它到底是过时了，还是只是暂时冷门。**强行决策必然出错，那就交给时间**，一个月后，用新的经验和新的行业上下文再判一次。

杜绝知识遗漏和误删，靠的不是更聪明的模型，是一个愿意承认"现在判不了"的机制。

### 五、回到那个最关键的东西：知识本体经验库

把所有经验交互节点拼起来，整个系统长这样：

```
                     知识本体经验库
              经验沉淀中枢 · 动态复用 · 反哺全链路
        ┌─────────────┴─────────────┐
        ▼                           ▼
   课程生成智能体               课程迭代智能体
        │                           │
   ↻ 经验（素材过滤）          ↻ 经验（迭代判定）
     素材过滤                    迭代判定
        │                           │
   ↻ 经验（内容创作）          ↻ 经验（知识库更新）
     内容创作                    知识库更新
        │                           │
   ↻ 经验（质量评估）
     质量评估
        │                           │
        └─────────────┬─────────────┘
                      ▼
                   课程输出 → 用户使用 → 用户学习体验 · 内容纠错建议 · 人工审核优化意见
                      ▼
              沉淀为标准化经验 ──── 回流 ────┘
```

**每一个核心环节，进去之前都要先拉经验：**

| 环节 | 拉取的经验 | 作用 |
|------|-----------|------|
| 素材过滤 | 历史过滤经验 | 精准筛掉无效、过时素材 |
| 内容创作 | 历史写作经验 | 优化提示词逻辑 |
| 质量评估 | 历史评估经验 | 统一 0–100 打分标尺 |
| 迭代判定 | 历史评估经验 | 校准过时判定阈值 |
| 知识库更新 | 更新经验 | 沉淀新经验、触发再生成 |

而经验的来源被彻底打通了两端：
- **用户端**：学习体验反馈、内容纠错建议
- **运维端**：人工审核意见、批注纠偏

两端的输入，全部沉淀为标准化经验数据，回流知识本体经验库，反哺下一轮生产与迭代。

这就是那句话的完整含义：**使用即训练，反馈即进化。**

**这里的架构判断：**
传统 AI 系统的模式是"静态训练、被动更新"，模型训练完成即固化，之后所有的改进都必须靠一次新的训练或一次新的人工运维推动。

而经验驱动的系统不同。**它的能力不长在模型参数里，长在经验库里。** 模型可以随时换、随时升级，但知识本体经验库是你自己跑出来的、别人拿不走的资产，而且它只会随着使用量增加而变厚。

所以结论是：**在模型能力快速趋同的今天，AI 原生系统的护城河不在模型选型，在于你有没有设计出一条让经验能沉淀、能复用、能反哺的知识本体闭环。**

> 有闭环的系统，越用越准。没闭环的系统，交付即巅峰。

### 六、这套架构最终换来了什么

**对用户：**
- 实时获取最新行业知识与前沿技术课程，规避陈旧知识误导
- 拿到的是图文音视频一体化的多模态内容，不是纯文字讲义
- 课程质量、更新精度、适配性随平台使用量持续提升

**对平台：**
- 大幅降低人工创作、审核、更新的运维成本
- 知识体系实现自动化、常态化迭代，摆脱人工运维的效率瓶颈
- 课程做到天级小时级更新

而从更长的时间维度看，随着用户数据积累和知识本体经验库持续扩容，知识筛选精准度、课程生成质量、迭代优化效率都会继续往上走。

**这是一条会自己变陡的曲线，而不是一条交付即封顶的直线。**

### 七、写在最后

这篇拆的是 AITutor AI 原生学习伙伴的自进化，但想说的其实不只是课程。任何 AI 原生系统，都应该问自己三个问题：

1. 我的系统，有没有地方在**沉淀**知识本体经验？
2. 沉淀下来的经验，有没有被**真正复用**回执行链路？
3. 用户的每一次使用、每一次纠错，有没有让系统**变得更强**？

三个都答不上来，那它只是一个"用了 AI 的系统"，不是 AI 原生系统。
