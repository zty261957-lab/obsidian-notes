# Skill 应该怎么写（编写方法全解）

> 配套《1_Skill编写模板》使用。核心心法一句话：**Skill = 触发词 + 提示词模板 + 执行流程；不是"更复杂的提示词"，而是"可调用的流程"。**

## 一、写之前：判断该不该封装成 Skill

你的工作满足以下条件越多，越值得写成 Skill：

- [ ] 每周 ≥2 次重复做同一类事（会议纪要、周报、反馈分析、PRD 初稿）
- [ ] 流程相对稳定（每次做法差不多）
- [ ] 产出可以被"模板化"（格式固定，如 4 板块纪要）
- [ ] 容易遗漏要素 / 每次手写长提示词

> 一次性任务、探索性任务 → 不封装，直接对话解决。**别为一次性工作造 Skill。**

## 二、写什么：SKILL.md 的完整结构

**格式 = YAML frontmatter（给 CLI 看）+ 正文 6 模块（给 AI 执行看）**

```plaintext
┌─ YAML frontmatter ──────────────────────────┐
│ name: meeting-minutes          ← 全小写+中划线 │
│ description: 做什么+何时用+触发词            │
└─────────────────────────────────────────────┘
┌─ Markdown 正文 6 模块 ──────────────────────┐
│ ① 触发词  /xxx                            │
│ ② 一句话描述  做什么+产出长什么样           │
│ ③ 输入约定  必填什么/可选什么              │
│ ④ 执行步骤  3-10 步按序                    │
│ ⑤ 输出契约  格式写死（板块+字段+路径）      │
│ ⑥ 约束  不能做什么/必须满足什么            │
└─────────────────────────────────────────────┘
```

## 三、每个模块怎么写（先想清楚再落笔）

### ① 触发词 + description：决定"AI 什么时候想起你"
- name/触发词/目录名三者必须一致（去掉 `/`）
- description 写 **"做什么 + 何时用 + 触发关键词"**，关键词越多触发越准（如：会议纪要、转写文本、/meeting-minutes、评审会、周会、复盘会）

### ② 一句话描述：给 AI 执行时读的
写"做什么 + 产出长什么样"，不用写何时用（那是 description 的活）

### ③ 输入约定：先想清楚"这个流程需要什么原料"
问自己 3 个问题：
1. 必须输入什么？（文件路径 / 粘贴文本 / 参数）
2. 什么能增强质量？（参考名单、背景文档、模板）
3. 缺了会怎样？（→ 写进约束：禁止编造，标"待补充"）

### ④ 执行步骤：按"人是怎么干的"拆解
- 3-10 步，每步一个动作，动词开头（读取/清洗/切分/提炼/提取/校验/输出）
- **清洗步骤别省**：真实输入总有噪声（口语词、重复、残缺）
- **校验步骤别省**：让 AI 对照输入自查（名单匹配、格式合规、粒度）

### ⑤ 输出契约：**写死**格式
这是"团队能不能复用"的分水岭：
- 几个文件？什么格式？路径规则？（如 `{输入目录}/报告_{日期}.md`）
- 几个板块？顺序固定？每个板块哪些字段？
- 表格列名写死、文末统计行写死

### ⑥ 约束：把"AI 会翻车的点"全列出来
训练营原话：约束就是防翻车。每个场景想一遍 AI 最可能犯的错：
| 翻车点 | 约束写法 |
|--------|---------|
| 编造人名/责任人 | "责任人只能从用户提供的名单匹配，找不到标'待指派'" |
| 把提议写成决定 | "无明确共识表述时写'待跟进'" |
| 口语词进产出 | "删除嗯/那个/就是说，合并重复段" |
| 粒度失控 | "行动项 1 人 1 天，太粗需拆分" |
| 数字模糊 | "'尽快/大概'标'待定'，禁止换算" |
| 输出格式漂移 | "单文档，固定 4 板块顺序" |
| 越权判断业务 | "只提炼不评判业务对错" |

## 四、写完怎么验证（自己测 3 轮）

1. **加载测试**：`/skills` 能看到吗？看不到 = frontmatter 问题（第一行必须 `---`）
2. **正常输入试跑**：给一份标准输入 → 对照输出契约逐项检查
3. **边界输入试跑**：残缺输入（缺名单/乱格式）→ 看 AI 是否按约束处理（标待定/待指派，而不是硬编）

> 训练闭环：试跑发现 AI 某处翻车 → **把翻车点写进约束** → 重跑 → 直到稳定。Skill 是"越用越稳"，不是一次写成的。

## 五、进阶：什么时候升级写法

| 你的 Skill 变得… | 升级方向 |
|------------------|---------|
| 模板/示例多（5 种图、深度报告） | 单文件 → **SKILL.md 当调度中心 + 外挂 templates/examples**（用到才加载，省上下文） |
| 任务重、环节独立（竞品分析） | 拆 **Subagent 编排**（并行/隔离并行/串行，多视角独立评审） |
| 要长出一个"项目"（原型/Demo） | **二段式**：SKILL.md 只 init + 项目自带 CLAUDE.md/scripts 接管日常维护 |
| 要团队共享 | 项目级 `.claude/skills/` 进 git；沉淀模板到 references/ |

> 判断准则：**只对当前项目成立的改动 → 改项目文件；对所有同类任务都成立的改进 → 才反哺 skill 本体。**
