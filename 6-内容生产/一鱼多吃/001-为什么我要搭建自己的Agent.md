# 为什么我要搭建自己的 Agent

## 原始素材

> 以下保留本轮原始表达，不将目标或设想补写成已经实现的结果。

1. 因为我想解脱我的双手。我觉得人是不应该一直坐在电脑面前办公的，更重要的是想法、判断及最终决策。
2. 目前写公众号成为我最重复、最烦的任务，因为我平时工作任务比较繁重。之前是一个字一个字码，现在在学习搭 Agent 去写，后面希望能够解放生产力。
3. 希望 Agent 能快速帮助我完成选题研究，用通俗易懂的话去写，让读者从文章中得到启发，并且跟着文章中的方法完成一件原本较难完成的事。
4. 文章的最终选题、脉络结构和主题思想必须由我判断。
5. 我希望以后去探索更多有意思的事：发现什么能干、为什么这么干、有没有更好的做事方法；再把这些探索记录和方法分享出来，让更多普通人能够跟着尝试。

## 已确认的观点

- 搭建 Agent 的目的不是让 AI 替代思考，而是把重复执行交给 AI，把人的时间留给想法、判断和最终决策。
- 公众号写作是当前希望优先改善的重复任务。
- 内容应该使用通俗易懂的表达，并给读者可以跟着实践的方法。
- 探索过程、失败、判断和更好的做事方法都值得被记录和分享。

## Agent 可以承担

- 根据目标和素材提供候选选题及选择依据。
- 整理原始素材，提取观点、事实和待核实信息。
- 根据已确认的结构生成草稿。
- 将专业概念改写成通俗易懂的表达。
- 根据人工反馈修改草稿，并记录修改原因。

## 必须由人决定

- 最终选题。
- 文章脉络与结构。
- 主题思想。
- 哪些观点代表本人立场。
- 哪些内容可以公开。
- 发布前终审与最终决策。

## 待确定

- 如何验证读者是否能够照着文章完成一件事。

### 文章任务卡

- 文章类型：个人实践与阶段性思考。
- 单一读者问题：想用 AI 减少重复工作时，哪些事情可以交给 Agent，哪些判断必须由自己保留？
- 一句话结论：搭 Agent 不是为了放弃思考，而是把重复执行交给 AI，把人的时间留给判断和最终决策。
- 预期读者动作：选出自己的一项重复工作，分别写下“AI 可以承担”和“必须由我决定”。

### 一、我真正想摆脱的，不是写作本身

- 从真实问题切入：本职工作繁忙，公众号写作又包含大量重复步骤。
- 说明过去经常一个字一个字写，真正消耗精力的不只是打字，还有选题、整理、研究和修改。
- 不把问题写成“我不想思考”，而是“我不想把有限精力反复花在机械执行上”。

### 二、开始搭 Agent 后，我先划了一条边界

- Agent 可以承担：选题研究、素材整理、候选方案、草稿生成、通俗化表达和修改记录。
- 人必须决定：最终选题、文章结构、核心思想、个人立场、公开边界和发布终审。
- 核心转折：是否使用 AI 不是关键，谁对最终判断负责才是关键。

### 三、这条边界怎样变成一套真实流程

- 输入：原始口述、账号定位、写作偏好和已有素材。
- Agent 推进：整理素材、提出三个角度、记录推荐理由。
- 人工确认：选择最终方向后，任务才进入下一阶段。
- 工作台记录：让“进行中—待确认—继续推进”成为看得见的状态，而不是在聊天记录里丢失。

### 四、目前跑通的是流程，不是结果

- 已验证：任务能够在 Agent 产出和人工确认之间往返流转。
- 尚未验证：文章质量是否稳定、是否真正节省时间、读者能否照着方法行动。
- 保留限制：只有跑过完整的初稿、终审和发布复盘，才能判断这套方法是否有效。

### 五、读者今天可以做的一个小动作

- 选择一项经常重复、自己又熟悉的工作。
- 画两列：左边写“AI 可以承担”，右边写“必须由我决定”。
- 只挑其中一个低风险步骤开始测试，并保留一个明确的人工确认点。
- 第一次的目标不是完全自动化，而是验证这次分工能不能把任务继续往前推。

## 初稿（已确认）

> 确认记录：用户已确认初稿方向与内容，可以进入标题方案阶段。

### 我为什么要搭建自己的写作 Agent：把重复执行交给 AI，把判断留给自己

最近，我在做一件看起来有点绕远的事：为自己搭一套公众号写作 Agent。

这里说的 Agent，不是点一下按钮就替我写完文章的机器。它更像一套有人机分工和确认节点的工作流程：AI 负责整理、生成候选方案和执行，人负责做关键判断。

我想做这件事，不是因为我不想写，也不是因为我想把思考交给 AI。恰恰相反，我希望把有限的时间更多地留给想法、判断和最终决策。

### 我想摆脱的，不是写作本身

我的本职工作比较繁重，公众号写作又是一项需要持续投入的事情。

以前写文章，我经常一个字一个字往外码。但真正消耗精力的，其实不只是打字。每写一篇文章，都要重新整理素材、选择角度、梳理结构、调整表达，再一遍遍修改。

这些事情里，有些需要我的经历和判断，有些却是反复出现的执行工作。如果每一步都从头手工完成，我很容易把精力消耗在流程里，反而没有足够的时间去想：我真正想说什么？这个观点是不是我的真实判断？这篇文章对读者到底有什么用？

所以，我想先从公众号写作开始，试着把重复执行交给 Agent。

### 开始搭 Agent 后，我先划了一条边界

我目前给 Agent 的工作主要有几类：整理原始素材、提取观点、给出候选选题、说明推荐理由、根据已确认的结构生成草稿，以及按照反馈继续修改。

但有一些事情，我不准备交出去：最终写哪个选题、文章采用什么结构、核心思想是什么、哪些观点代表我的立场、哪些内容可以公开，以及最后要不要发布。

这条边界对我很重要。

因为使用 AI 最容易出现的误区，不是它写得不够快，而是它给出了一个看起来完整的答案，人就顺手接受了。如果连选题、立场和最终发布都不再判断，那节省下来的可能不是重复劳动，而是思考本身。

我目前的理解是：是否使用 AI 不是关键，谁对最终结果负责才是关键。

### 我把这条边界放进了一条真实流程

这一次，我没有直接对 AI 说“帮我写一篇文章”，而是先建立了一张内容任务卡。

我先留下自己的原始表达，再让 Agent 从素材中整理出三个选题角度，并说明每个角度的核心观点、读者收获和风险。随后，由我确认最终方向。

方向确定后，Agent 只搭文章结构，不写正文。结构再次经过我的确认，任务才进入生成初稿这一步。

在工作台里，这个过程被记录成几个清楚的状态：正在推进、等待我确认、确认后继续推进。这样一来，任务不会停留在一段很长的聊天记录里，我也能看到现在走到了哪里、下一步该做什么。

到写下这篇初稿时，这条流程已经完成了选题和结构两次人工确认，并走到了初稿审核。

### 目前跑通的是流程，不是结果

我现在能确认的，只是这张内容任务卡可以在 Agent 产出和人工确认之间往返，任务能够继续向前走。

但这还不能证明文章质量已经稳定，也不能证明它真正节省了多少时间，更不能证明读者看完之后一定能够行动。

这些问题，要等初稿修改、发布和后续复盘完成后，才有可能得到阶段性的答案。如果以后每篇文章都要花更多时间修正 Agent 的输出，那这套流程仍然需要调整。

所以，我不会把这次尝试说成“已经搭好了一个能自动写公众号的 Agent”。更准确地说，我只是先跑通了其中一小段：让 AI 负责执行，让人在关键节点做决定，并把整个过程留在工作台上。

### 你也可以先做一个很小的测试

如果你也有一项经常重复、自己又比较熟悉的工作，可以先拿出一张纸，画成两列。

左边写“AI 可以承担”，例如整理资料、生成候选方案、检查遗漏；右边写“必须由我决定”，例如目标、取舍、公开边界和最终确认。

然后只选择左边一个低风险的步骤交给 AI，同时在它后面保留一个明确的人工确认点。

第一次不用追求完全自动化。先看看这次分工能不能让任务继续向前走，也看看 AI 的输出是否真的值得进入下一步。

这也是我现在搭建 Agent 的起点：不是为了不再思考，而是把重复执行交出去，把时间留给更重要的判断。
