# 为什么写作 Agent 必须保留人工确认点

## 原始素材

- `CONTENT-001` 已实际走过选题角度、结构、初稿、排版和发布前检查等环节。
- 过程中真正决定内容方向的，不是 Agent 一次性生成完整结果，而是人在关键节点做选择和确认。
- 工作台已能显示任务所处阶段、是否等待确认、下一步动作和任务入口。
- 当前能够确认的是“任务可以暂停、等待人判断，再继续推进”；尚未验证效率提升比例或内容质量提升幅度。
- 本轮只使用已验证的本地流程事实，未做外部热点与对标文章研究，不把该方向描述为行业趋势。

## 已确认的观点

- 人工确认点不是自动化失败，而是写作 Agent 的控制机制。
- Agent 适合承担搜集、整理、生成候选项和执行；人负责方向、立场、边界和最终判断。
- 一个有效的工作台，不只要显示“做到了哪”，还要明确“为什么停下”和“下一步由谁做什么”。
- 在角度确认前不进入正文，避免 Agent 把未确认的方向继续放大。

## Agent 可以承担

- 从已有素材中提炼不同的选题角度。
- 说明每个角度的核心观点、读者价值和写作风险。
- 推荐一个最适合当前任务目标的角度。
- 在用户确认后，再继续生成文章结构和初稿。

## 必须由人决定

- 最终采用哪个选题角度。
- 哪些个人经历可以公开，哪些只能作为内部素材。
- 文章更偏个人实践、风险提醒，还是工作台方法。
- 是否进入下一阶段。

- 可用素材：`CONTENT-001` 的真实推进过程，以及工作台里“所处阶段 / 等待我确认 / 下一步动作”的设计。
- 写作边界：只讲已经跑通的状态流，不夸大为完整内容操作系统，也不虚构效率数据。
- 推荐理由：最能验证工作台第二条任务链路，与 `CONTENT-001` 的宏观观点有区分，同时能产出明确、可复用的方法。

### 角度 2

**标题方向：我为什么不让写作 Agent 一次写完：3 个必须由人决定的节点**

- 核心观点：方向、结构和发布边界应由人确认，Agent 再继续执行。
- 读者价值：帮助读者为自己的写作流程设置三道人工确认门。
- 可用素材：`CONTENT-001` 中从选题到初稿、排版与发布前确认的实际节点。
- 写作风险：与上一篇“把时间留给判断”的主题较近，需要避免重复表达。

### 角度 3

**标题方向：AI 输出看起来越完整，越需要你保留最后判断**

- 核心观点：完整、流畅的输出容易让人跳过判断，而确认点能迫使人重新检查立场、事实和公开边界。
- 读者价值：提醒读者识别“看起来完成”和“真正可以采用”的差别。
- 可用素材：选题、初稿、排版和发布前检查中出现的多次人工确认。
- 写作风险：观点性更强，如果缺少更多具体案例，容易写成泛泛的 AI 风险提醒。

## 文章结构草案

> 本轮只搭建文章骨架，不写正文。结构确认后，再进入初稿阶段。

### 文章任务卡

- 文章类型：个人实践与工作台方法。
- 单一读者问题：把任务交给 Agent 后，怎样判断它应该继续做，还是停下来等人确认？
- 一句话结论：人工确认点不是自动化的中断，而是防止 Agent 越过方向、立场和公开边界的控制机制。
- 预期读者动作：为自己的一项 Agent 任务补上“进行中、等待确认、确认后继续”三个协作阶段，并明确每个阶段的下一步动作。
- 事实边界：目前只验证了工作台能记录任务、显示等待确认并在人工选择后继续流转；不宣称已经证明效率或内容质量提升。

### 一、我让 Agent“继续，直到需要我确认”之后

- 从 `CONTENT-001` 的真实操作切入：Agent 可以连续执行，但必须知道什么时候停。
- 如果没有明确停点，流程容易走向两个极端：频繁追问，或带着错误方向一路生成。
- 提出全文问题：哪些步骤可以自动推进，哪些地方必须把判断交还给人？

### 二、状态一：进行中——边界清楚时，让 Agent 执行

- 已有材料和目标明确时，Agent 可以整理素材、生成候选项、记录结果和准备下一步。
- “进行中”不代表 Agent 可以自行决定所有事情，只代表当前动作在已授权范围内。
- 工作台必须同时记录当前阶段和下一步动作，避免“正在做”变成模糊状态。

### 三、状态二：等待我确认——遇到判断时，主动停下来

- 选题方向、文章结构、个人立场、公开边界和最终交付不能靠 Agent 默认猜测。
- “待确认”需要说明正在等什么，而不是只显示一个暂停标签。
- 用 `CONTENT-002` 当前状态作为例子：角度确认后，任务进入“文章结构待确认”，正文没有提前生成。

### 四、状态三：确认后继续——把人的选择写回任务

- 用户确认不能只留在聊天记录里，要写回任务卡，成为下一步执行依据。
- 确认后更新“所处阶段”和“下一步动作”，Agent 才继续搭结构、写初稿或进入下一关。
- 重点不是自动化跑得多远，而是每次继续都能追溯到哪一次人工决定。

### 五、最小工作台只需要五个可见字段

- 当前任务：现在处理的具体内容是什么。
- 所处阶段：任务已经走到哪一步。
- 是否等待你确认：当前执行权在 Agent 还是在人。
- 下一步动作：确认后具体做什么。
- 任务入口：回到原始任务卡查看素材、决策和记录。
- 收束为读者动作：先拿一个真实任务测试这五个字段，不急着搭复杂系统。

## 初稿（已确认）

> 确认记录：2026-09-26，用户确认初稿通过。

**工作标题：一个任务什么时候该停下来等人？我用 3 个状态给写作 Agent 加上确认点**

最近，我在用真实内容任务测试自己的写作 Agent。

测试时，我没有让它一口气交出完整文章。我会让它先整理素材，再给出三个选题角度；我确认方向以后，它再搭结构。结构通过，才进入初稿。

这样做看起来慢了一点，但它帮我看清了一个很实际的问题：把任务交给 Agent 以后，它什么时候应该继续做，什么时候必须停下来等人？

如果每一步都回来问，Agent 只是把操作换了一个地方，我还是要一直盯着。如果它从头跑到尾，前面一旦理解错了，后面生成得越完整，返工可能越多。

这次实践让我看到，确认点承担的是控制作用。它让 Agent 在边界清楚时继续执行，遇到需要人判断的地方主动停下。

### 一、我说“继续”，不代表把判断也交出去

在第一条内容任务里，我连续几次对 Agent 说“继续下一步”，后来又补了一句：“继续，直到需要我确认。”

这句话背后其实有两个要求。

第一，已经明确的事情，不要反复问我。第二，涉及方向和责任的决定，不要替我猜。

真正难的地方不在于 Agent 会不会生成内容，而在于任务里常常混着两类动作：一类是整理、归纳和执行，另一类是选择、取舍和判断。如果没有把它们分开，“自动继续”就很容易变成“默认替我决定”。

于是，我在工作台里保留了三个协作阶段：进行中、等待我确认、确认后继续。

### 二、状态一：进行中

当输入、目标和边界已经明确时，Agent 可以继续执行。

比如，读取现有素材、整理已经说过的观点、生成三个差异明确的候选角度，或者把处理结果记录回任务卡。这些动作可以检查，也可以返工，不需要每做一步都暂停。

但“进行中”不能只显示三个字。工作台还要告诉我，任务现在走到哪一步，下一步准备做什么。否则同样是“进行中”，我无法判断它是在整理素材，还是已经开始写正文。

### 三、状态二：等待我确认

当任务从执行进入判断，就应该停下来。

我目前保留的确认点包括：最终选题、文章结构、个人立场、公开边界和正文终审。这些选择会改变后面的内容，也关系到哪些话真正代表我。

“待确认”同样不能只是一个暂停标签。它需要说明正在等我确认什么。

这篇文章本身就是一个例子。三个选题角度生成后，任务停在“选题角度待确认”。我选择角度 1，Agent 才继续搭结构。结构生成后，它又停在“文章结构待确认”。直到我确认结构，任务才进入现在的“初稿待确认”。

这样一来，我打开工作台就能知道，任务没有卡住，它是在等一个必须由我完成的判断。

### 四、状态三：确认后继续

我在聊天里回复“1”或“结构通过”，还不算完成了一次交接。

这个选择必须写回任务卡：确认了什么、任务进入哪个阶段、下一步由 Agent 做什么。只有这样，下一次打开任务时，之前的决定才不会埋在聊天记录里。

比如这次，我选择角度 1 后，任务卡增加了“已确认选题”，所处阶段改为“文章结构待确认”。结构通过后，阶段再变成“初稿待确认”，下一步动作也随之更新。

这里的“继续”有依据，也有范围。Agent 可以沿着已确认的方向往下做，但不能把这次确认扩大成后续所有决定的授权。

### 五、我的最小工作台只显示五件事

为了让这套过程看得见，我没有先搭一个复杂系统。目前的“IP 内容进行中”面板只显示五个字段：

- 当前任务：正在处理哪一条内容。
- 所处阶段：任务已经走到哪一步。
- 是否等待我确认：当前执行权在 Agent 还是在我。
- 下一步动作：确认后具体做什么。
- 任务入口：回到原任务卡查看素材、选择和处理记录。

它现在只能证明一件事：同一个任务可以在 Agent 执行和人工判断之间往返，而且每次停下都有明确原因。

至于这套方法是否真的能节省时间、能不能稳定提高内容质量，我还没有足够结果。要继续跑更多真实任务，再看返工次数、人工修改和最终内容表现。

如果你也在搭自己的 Agent，可以先拿一个真实任务做测试。不要急着追求全自动，先写下这五行：

> 当前任务：  
> 所处阶段：  
> 是否等待我确认：  
> 下一步动作：  
> 任务入口：

然后只检查一个问题：当任务需要你做判断时，它能不能停在正确的位置。
