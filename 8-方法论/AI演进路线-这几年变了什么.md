# 这几年 AI 的演进路线（基于 obs 沉降材料梳理）

> **材料范围**：`0-信息输入/` 公众号 31 篇 + 电子书 PDF 5 份 + 专题研究
> **方法**：不看单篇，看"瓶颈往哪移"
> 整理：Hermes ｜ 2026-11-11

---

# ⭐⭐⭐ 一、一句话：这不是"模型越来越强"的故事

> ### **这是一条"瓶颈不断向右移动"的链。**

```
模型不够强 → 搞提示词工程
提示词不够用 → 搞 RAG（补知识）
知识补了还是答不准 → 搞 Agent（让它能执行）
单个 Agent 干不完 → 搞多 Agent 编排
编排有了但效果不稳 → 搞 Harness（运行系统）
Harness 有了但不知道好不好 → 搞评测与可观测
单点都好了但组织没提效 → 搞流程重构（← 2026 年到这里）
```

**⭐⭐ 每解决一环，瓶颈就转移到下一环。**
**理解这一点，比记住任何单个技术名词都有用。**

---

# ⭐⭐ 二、五条演进主线

## 主线 1｜技术范式：从"调提示词"到"造运行系统"

| 阶段 | 时间 | 核心 | 解决的瓶颈 | 暴露的新问题 |
|------|------|------|-----------|-------------|
| **① 提示词工程** | 2023 | 手工调 prompt、few-shot | 模型不会按格式输出 | 知识过时、幻觉 |
| **② RAG 检索增强** | 2023-2024 | 向量库 + 检索 Top K 注入上下文 | 知识时效性、私域知识 | ⚠️ **语义相似 ≠ 工程相关**；颗粒度不一致；TopK 结构性没保证 |
| **③ Agent / 工具调用** | 2024-2025 | 模型能调工具、多步执行（ReAct、CoT） | 只能对话不能干活 | 单 Agent 干不完复杂任务 |
| **④ 多 Agent 协作** | 2025-2026 | Agent Team、A2A 协议、编排层 | 复杂任务要分工 | ⚠️ **能力相互冲突，难以形成稳定协作**（Muse）|
| **⑤ Harness / 上下文工程** | 2025 底-2026 | Agent = Model + Harness | 同一模型表现不稳 | Harness 本身怎么优化、怎么不退化 |
| **⑥ Harness as a Service** | **2026-11** | 运行系统变成独立商品 | 企业不想自己维护 | ⚠️ Harness 优化会退化（SWE-bench 94%→32%）|

### ⭐ 2026 年最大的结构性变化

**竞争焦点从"模型"转到了"模型外面那一层"**：

| 时间 | 事件 |
|------|------|
| **2025 底** | Anthropic 发现上下文耗尽后接不上 → 改进 Harness，**每阶段结束保存进度，下一轮读取继续** |
| 2026-02 | OpenAI 披露 Codex 网页/CLI/IDE **共用同一套 Agent 运行系统** |
| 2026-02 | OpenAI 招募 OpenClaw 创始人（无基础模型的公司靠运行系统吸引了大量用户）|
| 2026-03 底 | 斯坦福 **Meta-Harness**：让 AI 根据失败记录直接改 Harness 代码（+7.7%，上下文 Token 降至 1/4）|
| **2026-04** | Anthropic 推出 **Managed Agents**（$0.08/会话小时）|
| 2026-07 | **Co-Harness**：先用失败记录改 Harness，再用优化后的数据训练模型 |
| **2026-08-13** | **DeepSeek 以 MIT 协议开源 Harness 全部框架代码**，提出「Everything is a Plugin」|
| 2026-08 | OpenAI 把 Codex 定位为**开放的 Harness 平台** |
| 2026-09 | OpenAI 推出 **Agents API**（托管运行环境）|
| 2026-10 | **南洋理工测 66 种模型 × Harness 组合**：换 Harness 甚至能改变模型之间的排名 |
| **2026-11-05** | **Kimi 发布 Hosted Agents，明确提出 Harness as a Service** |
| **2026-11-07** | ⭐ **微软白皮书：同一个 Claude Opus 4.8，只换 Harness，复杂任务通过率 +22.1 个百分点**；调用次数翻倍，Token 反而 -21% |
| 2026-11 | **HarnessFlow**：自动搜索更好的 Harness 设计，六类任务平均 +10.89 个百分点 |

**⭐⭐ 这段可以概括成一句**：
> **"2026 年真正变化的不是模型，是模型外面那一层。"**

## 主线 2｜软件研发流程：从"AI 帮我写"到"AI 端到端做，人做判断"

| 阶段 | 时间 | 形态 | 人的位置 |
|------|------|------|---------|
| **① AI 代码补全** | 2023-2024 | Copilot：人写，AI 补全下一行 | 生产者 |
| **② AI 写代码，人 review** | 2025 | Cursor / Claude Code：AI 出大段代码 | 审查者（逐行）|
| **③ AI 端到端，人做判断** | **2026** | 需求→方案→编码→审查→部署 全链路 AI 跑 | ⭐ **判断者（不再逐行）** |
| **④ 组织级编排** | 2026 起 | 多 Agent 接力、角色重定义 | 决策者 + 知识供给者 |

### ⭐⭐ 关键实证（腾讯 PUBG，2026）

> **对照组：7 个服务 · 3 个月 · 16 万行生产代码、11 万行测试代码，没有一行是人写的。**

但结论反直觉：
> **"人的工作量没有减少，只是从「落笔」挪到了「拍板」。"**
> **"机器提供事实，人做判断。"**

### ⭐⭐ 关键实证（腾讯 OK 平台，2026-04~06）

| 数据 | 值 |
|------|-----|
| 提交需求 | 254 条 |
| AI 端到端完成 | **172 条（68%）** |
| **51% 的需求在 2 小时内完成** | （传统 3~5 个工作日）|
| ⚠️ 全部需求的覆盖率 | **约 30%**（两个数别混用）|

**他们在哪设了什么门**：
- **需求质量门**：AI 先复述理解 → 顺着挖 → 极模糊时给 2-3 种解释让人选 → 四项硬门槛（做什么/为谁做/关键业务规则/验收标准）→ 可行性 7 维打分 ≥60 才放行
- **技术方案门**：按依赖图排序（不是重要性）、垂直切片、粒度控制（超 5 文件必须拆）、插检查点、**对自己方案找茬**、**待确认问题提前暴露**
- **编码门**：简单优先（"三行重复代码好过一个过早的抽象"）、范围纪律

## 主线 3｜人的位置：从"执行者"→ 上移到"判断"和"决策"

| 代际 | 人的角色 | 具体表现 |
|------|---------|---------|
| **AI 工具期** | 操作者 | 人用 AI 当插件 |
| **Copilot 期** | 生产者 + 审查者 | 人写、AI 补、人改 |
| **Agent 期** | 审查者 | 读 AI 的产出，逐行审 |
| **2026 端到端期** | ⭐ **判断者** | 审"意图"不审"语法"；只审 AI 标记的关注点 |
| **组织级期** | ⭐⭐ **决策负责人** | "人不再是系统知识的唯一检索器，而是**知识质量和决策权的最终负责人**"（阿里）|

### 人的四个不可替代节点（腾讯 OK 平台的实践总结）

1. **决策与方案选型**（AI 枚举利弊，人拍板）
2. **补充隐性上下文**（架构背景、历史包袱、团队约定——只在人脑里）
3. **异常识别与干预**（AI 缺全局视角，会漏）
4. **最终的价值判断**（"该实现什么"不该交给 AI）

**⭐⭐ 一个必须注意的约束**（Google 智能体设计模式）：
> **HITL（人机协同）有"固有的可扩展性不足"** ——
> **不能全程人工确认，必须选准"在哪几个点让人介入"。**

## 主线 4｜知识与上下文：从"塞文档"到"前置强注入 + 结构化"

| 阶段 | 做法 | 问题 |
|------|------|------|
| **① 塞文档** | 全塞进 prompt | 装不下、噪音大 |
| **② RAG** | 向量检索 Top K | ⚠️ **语义相似 ≠ 工程相关**；颗粒度不一；可能互相矛盾 |
| **③ 结构化知识库** | 按领域建模（原则/场景/实践/历史）| 建库成本高 |
| **④ 前置强注入** | 平台在调用前把相关知识打包塞进入参 | ⚠️ 需要平台侧判断"这次要什么" |
| **⑤ 渐进式披露** | 不预加载，按任务推进逐层加载 | 需要可靠的"下一步该加载什么"判断 |

### ⭐⭐ 三个反直觉的结论

**① "AI 不知道自己不知道什么"**（腾讯 OK 平台）
> 早期让 AI 自己决定什么时候查 —— 但**它意识不到"我现在该查一下历史踩坑"**。
> 改成**平台侧前置强注入**后，知识注入率从不稳定提升到 **>90% 的确定性覆盖**。

**② "不首推 RAG"**（阿里架构师 Agent）
> **"知识是有结构的，更适合被结构化索引和理解。
> 信息（比如新闻类内容）是结构化松散的，更适合被平行/平铺化检索。"**

**③ "过期的知识污染上下文，比没有知识更危险"**（腾讯）
> 三道防线：**TTL 有效期** / **Agent 反馈通道（`knowledge_feedback`）** / **随 commit 自动刷新**

## 主线 5｜评测与度量：从"看准确率"到"看失败归因和业务后果"

| 阶段 | 度量什么 | 问题 |
|------|---------|------|
| **① Benchmark** | 模型跑分 | 跟真实业务无关 |
| **② 准确率 / 通过率** | 单次执行对不对 | ⚠️ **AI 犯错是规模问题不是概率问题** |
| **③ 题集 + 双门槛** | 黄金题集、执行完整率≥90% + 结果分≥80 | 要持续维护题集 |
| **④ 失败归因 + 可观测** | 五类归因（数据/模型/工具/规则/环境）+ Trace | 需要一开始就设计字段 |
| **⑤ 业务后果** | 任务成功率、人工接管率、越权动作、单任务成本 | — |

### ⭐⭐ 三条最硬的判断

**① "评测的核心是构建题集，不是搭评测平台"**（腾讯）
> **"17 万行的平台只留下两个分数，16 次跑数改掉一个策略。"**
> **"凡是能脚本化的环节，都不值得当成工程去建设。"**

**② "错误的评测信号比没有更危险"** —— 它会把迭代引向根本不存在的问题。

**③ 度量观的反转（2026-09，Meta）**
> ⚠️ **废掉了"Token 使用量考核"** —— 因为它是**投入量不是产出量**，而且**可刷**。
> **改成结果指标**：输出质量 / 速度 / 问题复杂度 / 承担范围。

# ⭐⭐⭐ 三、三个真正的拐点

## 拐点 1｜2025 年底：发现"上下文断了，任务就断了"

> Anthropic 发现：**上下文窗口耗尽，新一轮对话往往无法接续此前的工作。**
> 解法不是更大的窗口，而是**改 Harness —— 每阶段结束前保存进度，下一轮读取继续**。

**⭐ 意义**：
> **从此"任务能不能跨会话继续"成了系统的能力，而不是模型的能力。**

## 拐点 2｜2026 年 2-9 月：从"个人提效"到"组织提效"被证明是两件事

**快手（2026-02）**首次系统披露：
> 工具层面 AI 代码生成率 1%→30%+，**个人主观体感 +20~40%**，
> 但**组织整体需求吞吐量没有明显提升，交付周期也没明显缩短**。

**腾讯（2026）**给出量化：
> **"角色间等待往往占交付周期的 40~60%。把每个人编码速度提升 50%，也解决不了这个等待问题。"**

**⭐⭐ 结论定性**：
> **个人提效是加法，组织提效是乘数 —— 乘数在"环节之间"，不在"每个人手里"。**

## 拐点 3｜2026 年 11 月：Harness 从"内部实现"变成"独立商品"

> **Kimi（11-05）提出 Harness as a Service；微软（11-07）用数据证明它值 22 个百分点；
> Anthropic、OpenAI、DeepSeek 全都开源或开放了自己的 Harness。**

**⭐ 意义**：
> **"谁能提供可靠的运行系统，谁就有机会影响模型的选择，以及 AI 如何参与真实业务。"**
> **文章最后点题的那个词：入口。**

# ⭐⭐⭐ 四、最重要的三个变化（如果只记三件事）

| # | 变化 | 一句话 |
|:--:|------|-------|
| **1** | **瓶颈从"生产"转到"衔接"** | 编码已经不是瓶颈了，**交接、判断、验证**才是 |
| **2** | **竞争焦点从"模型"转到"运行系统"** | 同一个模型，换 Harness 差 22 个百分点，甚至能改变模型排名 |
| **3** | **新增了一个维度：可信** | AI 做功能很强，但**"失败不可见"** —— 这不是功能问题，是价值观问题 |

# ⭐ 五、一条贯穿始终的反直觉

> ### **"AI 交付功能的能力，明显强于它交付「让失败可见」这种纪律的能力。
> ### 因为前者是需求，后者是价值观。"**（腾讯）

**这条为什么重要**：
> **前面四条主线都在讲"怎么让它跑起来"，只有这一条讲"跑起来怎么不出事"。**
> **而且它是唯一一条"技术解决不了、只能靠设计"的问题。**

# ⭐⭐ 六、接下来往哪走（材料里的趋势判断）

| 方向 | 依据 |
|------|------|
| **Harness 会继续分层**（通用 Harness / 项目 Harness / 业务线 Harness）| 微软 +22pp；但 SWE-bench 94%→32% 说明通吃不了 |

| **评测从平台转向题集 + 失败归因** | 腾讯"题集不是平台" |

| **人从"检索器"变成"决策负责人"** | 阿里：人不是知识检索器，是知识质量和决策权的最终负责人 |

# ⭐ 一句话

> **这几年 AI 的演进，不是"模型越来越强"，是"瓶颈不断向右移动"：**
> **提示词 → RAG → Agent → 多Agent → Harness → 评测 → 流程重构。**
>
> **⭐⭐ 三个拐点**：
> **① 2025 底：上下文断了任务就断了 → Harness 有了存在理由**
> **② 2026 上半年：个人提效 ≠ 组织提效被证明 → 瓶颈在环节之间（等待占 40-60%）**
> **③ 2026-11：Harness 变成独立商品 → 竞争焦点从模型转到运行系统（+22pp）**
>
> **⭐⭐⭐ 而贯穿始终的那一条**：
> **AI 最不擅长的不是做功能，是"让失败可见"——因为后者是价值观，不是需求。**
