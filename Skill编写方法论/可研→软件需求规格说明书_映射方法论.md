## 二、五种映射类型（判定与处理）

| 类型 | 判定标准 | 处理方法 | 本次实例 |
|------|---------|---------|---------|
| **① 直接搬运** | 可研原文可直接使用（清单/表格/段落） | 原名原值搬运，末尾标〔来源：可研 X.X〕 | 参考资料 15 条、岗位 8 条、性能指标 5 项 |
| **② 结构重组** | 可研有内容但视角不同，需重新组织 | 按目标章节的提问重新归类 | 技术路线+架构+实施 → 假设/限制/依赖 4 项 |
| **③ 推导生成** | 目标章节内容可由可研内容推导（不新增事实） | 按规则推导，标"推导" | 用例（106 条 = 功能点 1:1）、角色（由岗位推导） |
| **④ 套话补全** | 可研无依据且属通用内容 | 用套话模板 + **差异化改写** | 编写目的、可维护性说明 |
| **⑤ 待补标注** | 可研无依据且属项目事实 | **一律标【待补】+ 责任人，禁止编造** | 460 处（依赖编号/输入输出编号/前置条件） |

> **铁律**：能搬运就不重组，能重组就不推导，**绝对不编造**——每个"待补"都要写明缺什么、找谁要。

## 三、三条定位规律（找来源的方法）

| 规律 | 说明 | 本次实例 |
|------|------|---------|
| **规律 1：一个可研章节 → 多个目标章节** | 可研某节信息量大，服务多个目标章节 | 可研 **2.1.2 建设内容** → 服务 4.3 架构、4.4 功能视图、4.5 功能点清单、6.1 业务信息（4 处） |
| **规律 2：多个可研章节 → 一个目标章节** | 目标章节需综合多个来源 | 1.2 术语 ← 1.1.1 现状 + 1.1.2 建设目标 + 2.1.2.3 数据工程 |
| **规律 3：章节名不同 ≠ 无关** | 按"提供什么信息"匹配，不按名称 | 可研 **2.1.7 项目管理** → 04-2 **4.1 岗位角色**（名字毫不相干，但岗位表在此） |

**定位口诀**：先问"这一章要回答什么问题"（拆题），再问"可研哪一节提供了这个答案"（定位）。

## 四、编号体系映射（关键）

可研的功能点表是 7 列扁平结构，04-2 要求三级编号体系：

| 可研列 | 04-2 编号 | 规则 |
|--------|----------|------|
| 一级业务需求 | `F_IC` **01**....（业务域，2 位） | 业务接入受理=01 / 供电方案智能编制=02 / 远程智能辅助验收=03 |
| 二级业务需求 | `F_IC01` **02**...（分组，2 位） | 同一业务域内顺序编号（业务受理智能模型=01、语音智能体构建=02…） |
| 二级功能（功能点） | `F_IC0102` **03**（序号，2 位） | 同组内顺序编号 |

**生成结果示例**：
```
F_IC010101  业务受理信息收集        （功能点编号）
BA_IC010101 业务受理信息收集        （业务步骤编号，与功能点一一对应）
UC_IC010101 业务受理信息收集用例     （用例编号，与功能点一一对应）
```
> 本次实证：可研 106 条功能记录 → 生成 106 个 F_IC + 106 个 BA_IC + 106 个 UC_IC

## 七、可迁移性（换目标文档时怎么做）

这套方法**不限于软件需求规格说明书**。换目标文档（如概要设计、验收材料）时：

1. **只重做"拆题"**（目标文档每章要回答什么问题）
2. **定位规律与映射类型通用**（①搬运 ②重组 ③推导 ④套话 ⑤待补）
3. **编号体系需按目标文档定**（04-2 是 F_IC/BA_IC/UC_IC；概要设计是 BP_IC/BA_IC/F_IC）
4. **三源验证永远适用**

> 已实践的三个目标文档：
> - 数据工程类《业务需求说明书》→ `fsr-to-reqspec/references/映射表.md`
> - 业务交易类《业务需求说明书》→ `fsr-to-reqspec/references/映射表-业务交易类.md`
> - **《软件需求规格说明书》（04-2）→ 本文件**

## 八、常见坑（本次踩过的）

| # | 坑 | 规避 |
|---|-----|------|
| 1 | **克隆参考段选错** → 正文继承标题样式（H1 从 7 膨胀到 17） | 克隆正文要用正文段作参考；填充后检查"长文本却是标题"的段落 |
| 2 | **连续 clone 同一参考段** → 顺序倒置（Q1-Q9 变成 Q9...Q1） | 链式锚点：用上一个新插入段作下一次的锚点 |
| 3 | **元素重排失效引用** → 段落丢失（177→169） | 重排后复核段落总数；去重判据不要带长度条件 |
| 4 | **合并单元格导致数据碎片**（"语音智"+"能体构建"） | 提取时对相邻重复值去重（`dict.fromkeys` 保序） |
| 5 | **表格行数不足** | 复制末行 XML 扩行（`deepcopy(table.rows[-1]._tr)`），保留格式 |
