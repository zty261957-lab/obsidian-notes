# 双智能体 + 知识本体：AITutor AI 原生自进化架构设计与落地案例剖析

## 📌 一句话概括

AITutor 用**两个职责分离的智能体 + 一个知识本体经验库**，把"内容生产"和"内容保鲜"都变成系统的自动能力——模型能力是买来的，**真正拉开差距的是系统上线后还能不能自己变强**。

---

## 🎯 核心观点（提炼）

1. **"跑通即巅峰"是 AI 应用的普遍困境**：Demo 阶段惊艳，上线三个月开始退化，半年后没人敢用——因为能力在交付那一刻被冻结了。
2. **知识半衰期已压缩到"周"**：更新速度低于知识过期速度，系统就在持续腐化。
3. **必须拆成两个智能体**：「新知识进来」（从无到有的生产）和「旧知识过期」（从有到优的判定）是**两个方向相反的问题**；一个智能体同时扛，**提示词互相污染、评估标准互相干扰**。职责分离在 Agent 架构里和微服务架构里一样重要。
4. **经验闭环是核心资产**：每一次执行前先拉历史经验（不是写死的规则），执行后反馈沉淀——形成"知识经验拉取 → 实时执行 → 反馈沉淀"的小闭环。
5. **批注有方向**：分正向与负向——**负反馈纠偏，正反馈固化**，比只做纠错的系统收敛快得多。
6. **"禁止人工手写正文"是硬约束**：不是为省人力，而是**保证经验闭环不被污染**——一旦允许人工插手，生成质量就无法归因到提示词和经验，反馈信号就断了。要让系统自己学，就必须让它承担全部输出。
7. **人工审核是核心进化触发点**：审核不通过 ≠ 打回重做，而是**自动沉淀问题经验 → 存入经验库 → 回流至素材筛选 → 基于新经验重新检索改写**。一次不通过 = 整条链路判断力的一次升级。
8. **白名单观察机制**：判不准的内容不强行决策，挂起观察一个月后自动回流重评——"杜绝知识遗漏和误删，靠的不是更聪明的模型，是一个愿意承认'现在判不了'的机制"。
9. **护城河不在模型选型**：能力**不长在模型参数里，长在经验库里**——模型可随时换，但经验库是自己跑出来、别人拿不走的资产，且随使用量增加而变厚。
10. **两条曲线的分野**：有闭环的系统**越用越准**；没闭环的系统**交付即巅峰**。

## 🧠 关键概念速查

| 概念 | 说明 |
|------|------|
| **双智能体架构** | 自动生成课程智能体（增量进化）+ 自动迭代课程智能体（存量焕新），底层共用知识本体经验库 |
| **增量进化链路** | 主题采集聚合（三层：采集 → 清洗 → 聚合）→ AI 课程生成（八步：领题 → 检索过滤 → 写课件 → 插画音视频 → AI 评估 → 合并上报 → 人工审核 → 上线） |
| **存量焕新链路** | 定时体检 → 拉取历史评估经验校准标尺 → 过时评估（框架/技术方案/内容准确性）→ 生成优化清单 → 人工复核（认可则重生成 / 存疑则白名单观察） |
| **知识本体经验库** | 经验沉淀中枢：沉淀 · 动态复用 · 反哺全链路。五个环节各有对应经验子库 |
| **经验拉取矩阵** | 素材过滤←历史过滤经验；内容创作←历史写作经验；质量评估←历史评估经验；迭代判定←历史评估经验；知识库更新←更新经验 |
| **经验来源双端** | 用户端（学习体验反馈、内容纠错建议）+ 运维端（人工审核意见、批注纠偏） |
| **三类批注** | 【检索资料】【课程生成】【AI 评估】——对应三个经验子库，各自反哺各自环节，互不干扰 |
| **使用即训练，反馈即进化** | 全文核心命题 |
| **静态训练 vs 经验驱动** | 传统系统：静态训练、被动更新（改进靠一次新训练或人工运维）；经验驱动系统：能力长在经验库 |

## 🔑 可迁移到我们工作（AI 原生研发体系）的点

1. **"沉淀经验"应当成为我们 Skill / Agent 设计的显式环节**——每个环节执行前后都应拉取/回写经验，而不是把规则写死在 prompt 里。
2. **职责分离原则**：生成类与质检类能力应拆开（文中"一个生成、一个审"→ 对应我们之前讨论的"形式审查 vs 内容审查"），避免提示词与评估标准互相污染。
3. **负反馈 + 正反馈双通道**：不只记录"错了"，也要记录"这样对，以后照此办"——收敛更快。
4. **审核不通过 = 经验沉淀触发点**：把人工复核意见结构化回流到链路起点，而不是只做局部修补。
5. **白名单观察机制可复用到指标/规范迭代**：判不准的先挂起观察，到期自动重评，避免强行决策。
6. **对外分享可引用的论断**：护城河 = 知识本体闭环，而非模型选型；"交付即巅峰 vs 越用越准"。

## ❓ 文中提出的三个自问（判断是否 AI 原生系统）

1. 我的系统，有没有地方在**沉淀**知识本体经验？
2. 沉淀下来的经验，有没有被**真正复用**回执行链路？
3. 用户的每一次使用、每一次纠错，有没有让系统**变得更强**？

> 三个都答不上来，那它只是一个"用了 AI 的系统"，不是 AI 原生系统。
